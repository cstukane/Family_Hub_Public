# Dashboard UI Redesign Plan

## Context

The Family Hub dashboard's current implementation diverges significantly from the intended design produced by the Claude Design function. The mockups show a polished, information-dense dark kiosk UI with a clear visual hierarchy — a large calendar occupying the primary content area, a right sidebar anchored by a large clock with stacked quick-access list items, three equal-width bottom tiles for Up Next / Shopping / Quick Timer, the Spotify miniplayer integrated into the bottom of the sidebar, and the sports ticker fixed at the screen edge. The current implementation has the miniplayer floating in the main content area, oversized app launcher buttons with text labels, a cramped bottom section, and a sidebar layout that doesn't match the intended proportions or type scale.

---

## Element-by-Element Changes

### 1. Calendar

**File:** `templates/base.html` (calendar section), `static/css/base.css`

**Changes:**
- No structural change to calendar data; purely styling/sizing.
- Ensure weekly time-slot view fills the full available height (not just `min-height: 80px` per cell — use `flex: 1` or `height: calc((100vh - var(--footer-h) - header) / slots)`).
- Today column: swap from a colored border to a filled circle on the day-number only (matching mockup's small cyan circle on "6").
- Remove the outer border from `.calendar-day`; use a very subtle `rgba` background instead for today highlight.
- Reduce event chip padding — current `padding: var(--spacing-xs) var(--spacing-sm)` makes chips too tall for dense days.
- Event chips: use colored left-border (4px) + very subtle same-color background tint. Remove the `border-radius: 12px` — use `4px` to match mockup's sharper, blocky events.

**CSS values to change:**
```css
/* Current */
.event-chip { border-radius: 12px; }
.calendar-day { min-height: 80px; border: 1px solid var(--border-color); }

/* Target */
.event-chip { border-radius: 4px; padding: 3px 6px; }
.calendar-day { min-height: 0; border: none; border-right: 1px solid var(--border-color); }
.calendar-day.current-day { background: rgba(0,180,216,0.06); border: none; }
.calendar-day-number.today { background: var(--primary-color); color: #000; border-radius: 50%; width: 24px; height: 24px; display: flex; align-items: center; justify-content: center; }
```

### 2. Right Sidebar

**File:** `templates/base.html` (sidebar section), `static/css/base.css`

#### 2a. Clock & Date
**Changes:**
- Increase clock font size: current max is `3.8rem` — target is ~`5.5rem–6rem` (the mockup's "2:20 PM" dominates the sidebar).
- Make clock weight `300` (thin) not `700` — mockup shows a light/thin numeral weight.
- Date line: `font-size: 0.85rem`, `color: var(--text-color-secondary)`, `letter-spacing: 0.04em`.
- Add `text-align: right` to match mockup right-alignment.
- Remove the `day-progress-bar` from its current position or reduce to 1px, flush under the date.

```css
/* Target */
.system-time { font-size: clamp(3.5rem, 4vw + 2rem, 6rem); font-weight: 300; letter-spacing: -0.02em; text-align: right; }
.system-date { font-size: 0.82rem; color: var(--text-color-secondary); text-align: right; letter-spacing: 0.04em; }
```

#### 2b. Quick-Access Buttons → Vertical List
**Current:** A flex-wrap grid of `.icon-button` elements (square buttons with icon + badge).  
**Target:** A stacked vertical list where each row has: icon (left), label text (middle), badge count (right). Similar to a settings list or iOS quick-access panel.

**HTML change in `base.html`:**
- Replace `.sidebar-header` button grid with a `<ul class="quick-access-list">` containing `<li>` rows.
- Each `<li>` has: `.qa-icon` SVG + `.qa-label` span + `.qa-badge` span (shown only if count > 0).

**CSS:**
```css
.quick-access-list { list-style: none; padding: 0; margin: var(--spacing-md) 0; display: flex; flex-direction: column; gap: 4px; }
.quick-access-item { display: flex; align-items: center; gap: var(--spacing-sm); padding: 10px var(--spacing-sm); border-radius: var(--border-radius); cursor: pointer; transition: background 0.15s; }
.quick-access-item:hover { background: var(--surface-color); }
.qa-icon { width: 20px; height: 20px; opacity: 0.7; flex-shrink: 0; }
.qa-label { flex: 1; font-size: 0.9rem; }
.qa-badge { background: var(--error-color); color: #fff; border-radius: 999px; padding: 1px 6px; font-size: 0.65rem; font-weight: 700; }
```

#### 2c. Weather Panel
**Current:** Uses the `weather_panel.html` partial with its own panel/header structure.  
**Target:** Weather integrated inline in the sidebar without a panel card border — just labeled sections "NEXT 5 HOURS" and day rows.

**Changes:**
- Remove the `.panel` wrapper (border/background) from weather when rendered in the sidebar — let it inherit the sidebar background.
- "NEXT 5 HOURS" label: `font-size: 0.65rem; text-transform: uppercase; letter-spacing: 0.1em; color: var(--text-color-secondary)`.
- Hourly row: 5 columns, each with icon + temp, minimal gap.
- Daily rows: icon (left), day name, high temp (right-aligned), low temp (muted right-aligned). Separated by a thin `1px` divider.
- Current temp: `font-size: 2.5rem; font-weight: 700` with condition text beneath.

#### 2d. Miniplayer — Move to Sidebar Bottom
**Current:** `.miniplayer` is `position: sticky; bottom: calc(var(--footer-h) + 40px)` inside the main scroll area.  
**Target:** Miniplayer lives at the **bottom of the sidebar**, docked, not floating in the main content.

**HTML change:** Move the `#miniplayer` element from the main content area into the sidebar, placing it after the weather section as the last child of `.sidebar`.

**CSS change:**
```css
/* Remove current sticky positioning */
.miniplayer { position: static; max-width: 100%; margin-top: auto; }

/* Sidebar becomes flex column so miniplayer pushes to bottom */
.sidebar { display: flex; flex-direction: column; }
.sidebar .weather-section { flex: 1; overflow-y: auto; }
```

**Size:** The compact `.miniplayer[data-state="collapsed"]` style (no progress bar / album art) is appropriate for the sidebar. Expand on click to show full controls.

### 3. Bottom Tiles (3-column row)

**Current:** A `.center-zone` card + `.commute-slot` + `.miniplayer-slot` in a flex row below the calendar. Layout is inconsistent and the miniplayer doubles as a tile.  
**Target:** Three equal tiles: **UP NEXT** | **SHOPPING** | **QUICK TIMER** (or **COMMUTE** when within commute window).

**HTML change in `base.html`:**
- Replace the current `.center-zone` + horizontal flex section with:
```html
<div class="bottom-tiles">
  <div class="tile tile-upnext">...</div>
  <div class="tile tile-shopping">...</div>
  <div class="tile tile-right">  <!-- Quick Timer or Commute -->
    <!-- conditionally rendered by Jinja config -->
  </div>
</div>
```

**CSS:**
```css
.bottom-tiles { display: grid; grid-template-columns: 1fr 1fr 1fr; gap: var(--spacing-md); margin-top: var(--spacing-md); }
.tile { background: var(--surface-color); border-radius: 12px; border: 1px solid var(--border-color); padding: var(--spacing-md); display: flex; flex-direction: column; gap: var(--spacing-sm); }
.tile-header { font-size: 0.65rem; font-weight: 700; text-transform: uppercase; letter-spacing: 0.1em; color: var(--text-color-secondary); display: flex; justify-content: space-between; align-items: center; }
.tile-badge { background: var(--primary-color); color: #000; border-radius: 999px; padding: 2px 8px; font-size: 0.65rem; font-weight: 700; }
```

#### 3a. UP NEXT Tile
- Re-use `calendar_upnext.html` partial content (event list) but strip the `.panel` wrapper; plug into `.tile.tile-upnext`.
- Each row: `time` (left, muted, ~`0.75rem`) + `event title` (right, `0.85rem`).
- "Now" label in cyan for the current event.
- "Tomorrow" label in muted color for next-day events.

#### 3b. SHOPPING Tile
- Re-use shopping partial content but rendered as two implicit columns within the tile (use `column-count: 2` on the list, or flex-wrap).
- Badge "7 Items" in tile header (matching the mockup's pill).
- Remove add-form from the tile view (full form remains in the modal/panel).

#### 3c. QUICK TIMER Tile
- Grid of preset buttons: 5 min, 10 min, 15 min, 30 min (2×2 or 1×4).
- Below: custom input + "Start" button.
- **Or COMMUTE tile** when `commute.alwaysVisible` or within commute window: show the commute metrics (ETA, route, status pill) without the map thumbnail (too small for tile format).

```css
.timer-presets { display: grid; grid-template-columns: 1fr 1fr; gap: var(--spacing-sm); }
.timer-preset-btn { padding: var(--spacing-sm); border-radius: 8px; background: var(--background-color); border: 1px solid var(--border-color); font-size: 0.9rem; font-weight: 600; cursor: pointer; text-align: center; }
.timer-preset-btn:hover { background: var(--primary-color); color: #000; border-color: var(--primary-color); }
.timer-custom-row { display: flex; gap: var(--spacing-sm); margin-top: var(--spacing-xs); }
.timer-custom-input { flex: 1; background: var(--background-color); border: 1px solid var(--border-color); border-radius: 8px; padding: var(--spacing-xs) var(--spacing-sm); color: var(--text-color); font-size: 0.9rem; }
.timer-start-btn { padding: var(--spacing-xs) var(--spacing-md); border-radius: 8px; background: var(--primary-color); color: #000; font-weight: 700; border: none; cursor: pointer; }
```
